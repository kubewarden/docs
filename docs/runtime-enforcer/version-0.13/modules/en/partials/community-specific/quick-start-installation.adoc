[#_prerequisites]
== Prerequisites

Before deployment, you need to prepare the following:

* A Kubernetes cluster (you can simply run a https://kind.sigs.k8s.io/[kind]
  cluster)
* `helm` installed locally
* `kubectl` installed locally
* {cert-manager-term} and `cert-manager-csi-driver` installed in the cluster

[WARNING]
====
Please check your environment satisfies the minimum
xref:reference/compatibility.adoc[{rte-short-name} requirements].
====

[#_install-cert-manager-and-cert-manager-csi-driver]
=== Install cert-manager and cert-manager-csi-driver

To install cert-manager, run the following commands:

[source,bash]
----
helm repo add jetstack https://charts.jetstack.io

helm repo update

helm install cert-manager jetstack/cert-manager \
	--namespace cert-manager \
	--create-namespace \
	--set crds.enabled=true \
	--wait
----

[NOTE]
====
For more information on configuring cert-manager, please visit the
link:https://cert-manager.io/docs/installation/helm[cert-manager documentation].
====

The `cert-manager-csi-driver` is used to automatically provision and mount TLS
certificates directly inside {rte-short-name} pods ({controller-term},
{agent-term}, and debugger). It does not create intermediate Secret
resources. To install it, run the following commands:

[source,bash]
----
helm install cert-manager-csi-driver jetstack/cert-manager-csi-driver \
	--namespace cert-manager \
	--wait
----

[#_deploy-rte-short-name]
== Deploy {rte-short-name}

Follow these simple steps from your local machine to get {rte-short-name} up and running:

[#_install-the-helm-chart]
=== Install the Helm chart

The chart does not deploy an {opentelemetry-collector-term}, and this guide
does not need one. {rte-short-name} records each {violation-term} in the
status of the policy. To export the violation events and metrics to your own
collector, see xref:howtos/telemetry.adoc[Export telemetry to an
OpenTelemetry collector].

[source,console,subs="+attributes"]
----
helm repo add kubewarden {runtime-enforcer-helm-chart}
helm repo update
helm install runtime-enforcer kubewarden/runtime-enforcer \
  --namespace runtime-enforcer \
  --create-namespace \
  --wait
----
