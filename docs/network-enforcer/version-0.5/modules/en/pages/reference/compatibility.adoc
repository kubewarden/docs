[#_overview]
== Overview

{ne-name} observes cluster traffic, proposes workload network policies, and enforces them in Kubernetes. It supports Istio ambient, Calico, and Cilium as providers.

[#_quick-reference]
== Quick Reference

[cols="2,3,5"]
|===
|Component |Requirement |Notes

|*Provider*
|`istio`, `cilium`, or `calico`
|Chart enum in `charts/network-enforcer/values.yaml` (`controller.provider.name`). Helm fails on any other value.

|*Architecture*
|x86_64, aarch64
|Fully supported.

|*Kubernetes*
|1.31+
|The chart sets `kubeVersion: ">= 1.31.0-0"`. It installs two `ValidatingAdmissionPolicy` resources (`admissionregistration.k8s.io/v1`): one guards the promote label, one guards the owner reference of a proposal. The API went GA in 1.30, but 1.31 is the oldest version the project tests against.

|*cert-manager*
|Required for every chart install
|Together with `cert-manager-csi-driver`, it supplies the admission webhook certificates. Disabling telemetry or provider TLS does not remove this requirement. The chart uses the same CSI driver for the Istio agents.

|*Linux distribution*
|To be determined
|
|===

[#_provider-matrix]
== Provider Matrix

`controller.provider.name` is required and must be one of `istio`, `cilium`, `calico`. Defaults to `istio`.

[cols="1,2,3,3"]
|===
|Provider |Minimum validated version |Transport and default endpoint |Policy backend

|*Istio (ambient)*
|1.30.3
|The controller polls each agent pod over gRPC with mutual TLS. Default agent port: `50052`.
|`spec.backend: istio` (Istio `AuthorizationPolicy`). +
The agent reads ztunnel access logs.

|*Calico*
|v3.32.1
|gRPC with mutual TLS to `goldmane.calico-system.svc:7443`. Default TLS mode `existingSecret`.
|`spec.backend: kubernetes` (Kubernetes `NetworkPolicy`). +
Goldmane flow stream.

|*Cilium*
|1.20.0
|gRPC with mutual TLS to `hubble-relay.kube-system.svc:443`. Default TLS mode `existingSecret`. Plain text on port `80` is an opt-in.
|`spec.backend: kubernetes` (Kubernetes `NetworkPolicy`). +
Hubble Relay flow stream.
|===

[#_istio-ambient-install-flags]
=== Istio ambient install flags

Set these values on the *Istio* Helm charts, not on the {ne-short-name} chart:

* `ztunnel`: set `logAsJson=true` so the agent can read the logs. Set `env.AUTHZ_POLICY_INFO_LOGGING=true` so ztunnel logs authorization decisions.
* `istiod`: use `profile=ambient` and set `pilot.env.AMBIENT_ENABLE_DRY_RUN_AUTHORIZATION_POLICY=true` for monitor mode.

For the equivalent `istioctl` command, see xref:quickstart.adoc#_option-1-istio-ambient[Install Istio ambient].

[#_provider-tls]
=== Provider TLS

Mutual TLS means both peers present a certificate.
A hop is one connection between {ne-short-name} and the provider.
TLS mode says where the certificates for that hop come from.

The chart configures mutual TLS for Istio agents. For Cilium and Calico, use `controller.provider.cilium.tls` or `controller.provider.calico.tls`.

[cols="1,3,2,2,3"]
|===
| Provider | Hop | Direction | Default mode | What you supply

| Istio
| Controller to each agent pod IP on port `50052` (`controller.provider.istio.agent.grpcPort`). No Service.
| Controller is the client. Each agent is a server.
| Chart-managed mutual TLS
| Install cert-manager and its CSI driver. The chart uses its CA to issue a certificate per agent and a separate controller certificate.

| Calico
| Controller to Goldmane at `goldmane.calico-system.svc:7443` (`controller.provider.calico.endpoint`)
| Controller is the client. Goldmane is the server. Mutual TLS.
| `existingSecret`
| Nothing in the release namespace. +
The controller reads Secret `calico-system/goldmane-key-pair` (`tls.crt` and `tls.key`) and ConfigMap `calico-system/goldmane-ca-bundle` key `tigera-ca-bundle.crt`. +
`issuer` uses cert-manager CSI and writes a client certificate to `/etc/provider/certs`. +
If you already have a client Secret in the release namespace, set `existingSecret.name` to that Secret, for example `net-enf-goldmane-client-certs`. Leave `existingSecret.namespace` empty. The chart mounts that Secret. It must contain `tls.crt`, `tls.key`, and `ca.crt`. +
`insecure` is rejected.

| Cilium
| Controller to Hubble Relay at `hubble-relay.kube-system.svc:443` (`controller.provider.cilium.endpoint`)
| Controller is the client. Relay is the server. Mutual TLS.
| `existingSecret`
| Nothing, when Secret `kube-system/hubble-relay-client-certs` exists (`ca.crt`, `tls.crt`, and `tls.key`). +
The server name is `ui.hubble-relay.cilium.io` (`tls.serverName`). +
`issuer` uses cert-manager CSI. The client certificate DNS name is `network-enforcer.hubble-relay.cilium.io`. +
`insecure` is plaintext. Clear `tls.serverName`. If the endpoint is still the default `:443`, the chart automatically overwrites the port to `80`.
|===

For Calico and Cilium, the chart sets `--provider-tls-mode` and the matching `--provider-tls-*` flags on the controller.
A cross-namespace Secret also renders a Role and a RoleBinding in that namespace.
The Role allows `get` on that Secret, and on the CA ConfigMap when one is set.
