= Documentation organization
:revdate: 2026-11-24
:page-revdate: {revdate}
:description: How the {gp-name} documentation is organized: introduction, quick start, explanations, how-tos, reference, and the pages about the project itself.
:doc-persona: ["kubewarden-all"]
:doc-topic: ["documentation", "organization"]
:doc-type: ["explanation"]
:keywords: {gp-name}, kubewarden, documentation, organization

The {gp-name} documentation has these parts:

* xref:introduction.adoc[Introduction]: what {gp-short-name} is, and how a
  policy selects the traffic that the WAF inspects.
* xref:quickstart.adoc[Quick start]: install {gp-short-name}, detect an
  attack, and then block it.
* _Explanations_: the architecture, the attachment of a policy to a gateway
  or a route, and the modes and the anomaly scoring of the WAF.
* _How-tos_: tasks for the operator, such as the attachment of a policy,
  custom rules, the tuning of false positives, production deployments, an
  emergency disable, and troubleshooting.
* _Reference_: the compatible versions, the upgrade path, the known
  limitations, and the custom resource definitions.
* xref:personas.adoc[For who?]: the people who use {gp-short-name}.
* xref:use-cases.adoc[Use cases]: what each persona does with it.
* Organization: this page.
* xref:glossary.adoc[Glossary]: the terms used in these pages.
* xref:disclosure.adoc[Security disclosure]: how to report a vulnerability.

Most of the content is in the _Explanations_, _How-tos_, and _Reference_
sections. The sections can overlap. The {gp-short-name} project follows the
link:https://diataxis.fr/[Diátaxis] documentation framework where it can.
