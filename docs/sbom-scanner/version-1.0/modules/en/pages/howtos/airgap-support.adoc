= Air Gap Support
:revdate: 2026-11-10
:page-revdate: {revdate}
:page-aliases: user-guide/airgap-support.adoc
:description: Run {sboms-name} in air-gapped environments with mirrored dependencies.

You can use {sboms-name} in air-gapped environments.

To run the scans, {sboms-name} currently needs the following external sources:

* Vulnerability Database
* Java Vulnerability Database
* VEX Hub (optional)

These external sources can be self-hosted in your private infrastructure to make the whole environment air-gapped.

[#_self_hosting_vulnerability_databases]
== Self-Hosting Vulnerability Databases

The following Vulnerability Databases are OCI images. You can host them in
your registry:

* https://github.com/aquasecurity/trivy-db/pkgs/container/trivy-db[`trivy-db`]
* https://github.com/aquasecurity/trivy-java-db/pkgs/container/trivy-java-db[`trivy-java-db`]

After you mirror the databases in your OCI registry, install {sboms-short-name}
with these values:

[source,shell]
----
helm install sbomscanner ./chart \
    --namespace sbomscanner \
    --create-namespace \
    --set scanner.trivyDBRepository="yourlocalregistry.example/sbomscanner/trivy-db" \
    --set scanner.trivyJavaDBRepository="yourlocalregistry.example/sbomscanner/trivy-java-db" \
    --set controller.defaultVEXHubResources=false
----

`./chart` is the path of the {sboms-short-name} chart that you copied to the air-gapped environment.

The command also disables the default VEX Hub resources.
See xref:#self-hosting-vex-hub[Self-Hosting VEX Hub].

[#self-hosting-vex-hub]
== Self-Hosting VEX Hub

To configure a VEX Hub repository, see this https://github.com/aquasecurity/trivy/blob/main/docs/docs/advanced/self-hosting.md#make-a-local-copy-1[guide].

Change `repository_url` in each applicable VEX file to point to an internal
registry.

Configure an HTTP server that provides the VEX files.

By default, {sboms-short-name} creates two `VEXHub` resources, `rancher` and `aquasecurity`. They point to the public `github.com/rancher/vexhub` and `github.com/aquasecurity/vexhub` repositories, which are unreachable in an air-gapped environment.
The install command in xref:#_self_hosting_vulnerability_databases[Self-Hosting Vulnerability Databases] sets `controller.defaultVEXHubResources` to `false`, so the chart does not create them.

To configure a VEX Hub in {sboms-name}, create a `VEXHub` resource with your local repository URL and apply it:

[source,yaml]
----
apiVersion: sbomscanner.kubewarden.io/v1alpha1
kind: VEXHub
metadata:
  name: local-vexhub
spec:
  url: "https://yourlocalrepo.example/"
  enabled: true
----
