= Common problems
:revdate: 2026-11-05
:page-revdate: {revdate}
:page-aliases: troubleshooting/common-problems.adoc
:description: Resolve common {sboms-name} issues and error conditions.

This page documents common errors that occur while users run
{sboms-name}. It explains how to correct these errors.

== Docker Hub pull rate limit reached

=== Problem

Scans end up in an error state with a message similar to:

[source,text]
----
You have reached your unauthenticated pull rate limit
----

This happens because anonymous image pulls from https://hub.docker.com/[Docker Hub] (`docker.io`) are subject to rate limiting. Once the limit is hit, further pulls are rejected until the window resets.

See the official Docker documentation for full details:

* https://docs.docker.com/docker-hub/usage/[Docker Hub usage and limits]
* https://docs.docker.com/docker-hub/usage/pulls/[Docker Hub pull rate limits]
* https://www.docker.com/increase-rate-limits/[Download rate limit overview]

=== Solution

Authenticate with Docker Hub. Then pulls count against your account limits
instead of the shared anonymous quota. See the Docker documentation for
available options:

* https://docs.docker.com/docker-hub/usage/#authenticate-to-increase-your-pull-rate-limit[Authenticate to increase your pull rate limit]
* https://docs.docker.com/subscription/[Subscriptions and higher limits]

After you get credentials, create a `kubernetes.io/dockerconfigjson` Secret
in the {sboms-name} installation namespace. Reference the Secret from the
applicable `Registry` resource. To propagate credentials to managed
registries, set the `authSecret` field in `WorkloadScanConfiguration`. See
xref:howtos/private-registries.adoc[Private Registries] for the procedure.

== CA bundle errors

=== Problem

The `ScanJob` of a registry fails.
The message of its `Failed` condition starts with `cannot resolve CA bundle:`, and then contains one of the errors in the table below.
To see the message, run this command, with the namespace of the `Registry`:

[source,bash]
----
kubectl get scanjobs -n <registry-namespace> -o yaml
----

{sboms-short-name} reads the CA bundle from the `spec.caBundleRef` or the `spec.caBundle` field of the `Registry`.
For a `Registry` that the workload scan manages, the namespace in the errors is the {sboms-short-name} installation namespace.

=== Solution

[cols="2,3",options="header"]
|===
|Error |Cause and fix
|`cannot get CA bundle ConfigMap <namespace>/<name>`
|The ConfigMap does not exist in the namespace that the error shows. Create the ConfigMap in that namespace, or correct the `name` in `caBundleRef`.
|`CA bundle ConfigMap <namespace>/<name> has no key "<key>"`
|The ConfigMap has no key with the name in `caBundleRef.configMap.key`. If you do not set `key`, the key is `ca.crt`. Add the key to the ConfigMap, or correct `key`.
|`cannot get CA bundle Secret <namespace>/<name>`
|The Secret does not exist in the namespace that the error shows. Create the Secret in that namespace, or correct the `name` in `caBundleRef`.
|`CA bundle Secret <namespace>/<name> has no key "<key>"`
|The Secret has no key with the name in `caBundleRef.secret.key`. If you do not set `key`, the key is `ca.crt`. Add the key to the Secret, or correct `key`.
|`CA bundle does not contain any valid PEM-encoded certificate`
|The value has no certificate in PEM format. Each certificate must start with `-----BEGIN CERTIFICATE-----` and end with `-----END CERTIFICATE-----`. Put the CA certificates in PEM format in the value. Earlier versions ignored this problem and used the trust store of the system.
|===

See xref:howtos/private-registries.adoc#_private_certificate_authority[Registries with a private certificate authority].
