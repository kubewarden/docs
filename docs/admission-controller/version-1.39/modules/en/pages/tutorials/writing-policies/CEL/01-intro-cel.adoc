The https://cel.dev[Common Expression Language (CEL)] is a general-purpose
expression language designed to be fast, portable, and safe to execute. CEL as
a language is memory-safe, side-effect free, terminating (programs cannot loop
forever), and strong & dynamically typed. You can learn more about CEL at
https://cel.dev[cel.dev], and practice it in the https://playcel.undistro.io[CEL
playground].

[#_cel_in_kubernetes]
== CEL in Kubernetes

CEL was chosen as the language for Kubernetes validation rules as CEL
expressions can be easily inlined into CRD schemas, and compiled and type-checked
"ahead-of-time" (when CRDs are created and updated). For these reasons
and its general characteristics, it's a perfect candidate for extending the
Kubernetes API.

Marked as stable with Kubernetes 1.30, one can use CEL on
https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy[ValidatingAdmissionPolicies]
and other validation rules. For more info, see the Kubernetes docs
https://kubernetes.io/docs/reference/using-api/cel[here].

[#_kubernetes_function_libraries]
=== Kubernetes function libraries

Kubernetes CEL validation rules have access to several function libraries:

* https://github.com/google/cel-spec/blob/v0.7.0/doc/langdef.md#list-of-standard-definitions[CEL standard functions]
* https://github.com/google/cel-spec/blob/v0.7.0/doc/langdef.md#macros[CEL standard macros]
* https://pkg.go.dev/github.com/google/cel-go/ext#Strings[CEL extended string function library]
* https://kubernetes.io/docs/reference/using-api/cel/#kubernetes-cel-libraries[Kubernetes CEL extension libraries],
with supplemental functions for lists, regex, URLs, authorizers, quantities,
optional types, numerical comparisons, etc.

[#_cel_in_kubewarden]
== CEL in {admc-name}

{admc-short-name} gives you two ways to run a CEL policy. Both ways run the
CEL expressions in the {policy-server}, and both give the expressions the
same function libraries:

* The CEL standard functions and macros
* The cel-go extension libraries
* The Kubernetes CEL extension libraries
* The {admc-short-name} CEL extension library, which exposes the
{admc-short-name} host capabilities as native CEL functions

The two ways differ in how the CEL expressions get to the {policy-server}.

[#_cel_in_kubewarden_cel_policy]
=== Interpreted: `cel-policy`

https://github.com/kubewarden/cel-policy[cel-policy] is a ready-made policy
that bundles the https://pkg.go.dev/github.com/google/cel-go[cel-go]
interpreter. You put the CEL expressions in the `spec.settings` of a
(Cluster)AdmissionPolicy, and the policy evaluates them at admission time.
There is no build step.

This is the option for a fast start and for prototyping.

[#_cel_in_kubewarden_compiled]
=== Compiled: CEL to WebAssembly

From {admc-short-name} v1.39.0, `kwctl` can compile a Kubernetes
`ValidatingAdmissionPolicy` into a dedicated WebAssembly module. The module is
specialized for the CEL code of your policy. It does not bundle the full CEL
runtime.

The compiled module is smaller and faster than `cel-policy`. You can publish
the module to an OCI registry and reuse it across clusters, like any other
{admc-short-name} policy.

This is the option for policies that you distribute, and for clusters where
the evaluation time matters. This feature is experimental.

=== Choose an option

| | `cel-policy` | Compiled to WebAssembly
